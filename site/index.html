A durable local scheduler

Every run.
Accounted for.

Cronlog is cron with a memory. It runs your scripts on a schedule and records every run: when it was due, when it started, how it ended and what it printed. It keeps all of it in one SQLite file on your machine.

Why it exists

Your jobs are small.
The uncertainty around them isn’t.

Plain cron starts a command and forgets it. Did it run? Did it fail? What did it print? Cronlog keeps the answer to each of those questions for every run.

✓ each scheduled slot claimed exactly once ✓ stdout and stderr kept with the run ✓ cronlog health exits 1 when something is wrong

01

Durable history

Every run is a record.

When it was due, when it started and finished, its status, exit code and duration. A run is never just a line in syslog.

RUN #412 · SUCCESS · 41213MS
$ cronlog history nightly-backup --limit 20

02

Captured output

The evidence stays local.

Cronlog reads stdout and stderr while the job runs, up to 256 KB each, and keeps them with the run. Large output never blocks the job.

STDOUT · STDERR · KEPT
$ cronlog logs sync --run-id 4821

03

Overlaps and timeouts

No pile-ups. No zombies.

A job never runs twice at once: a slot that comes round while it is still running is recorded as skipped. A timeout kills the job's whole process tree, not just the first process.

OVERLAP · SKIPPED AND RECORDED
$ cronlog add --name sync --schedule "every 15 minutes" --timeout 10m -- ./sync.sh

04

Health checks

It tells you when it’s not okay.

The daemon checks in every 30 seconds. cronlog health reports a daemon that has stopped, a run that is overdue, a job failing again and again, or a run stuck past its timeout, and exits 1 so a watchdog can act.

EXIT 1 · 2 PROBLEMS
$ cronlog health || notify "cronlog needs a look"

05

Daylight-saving safe

The clock changes. Your jobs don’t notice.

Times are stored in UTC. Interval jobs keep an even pace through the night the clocks change. A daily at job keeps its local time: when the clocks go back it runs once, and when they jump forward it runs as soon as the clock jumps.

NEXT RUN · 07:00 -05:00
$ cronlog add --name digest --schedule "daily at 07:00" -- ./digest.sh

06

Retention

History that stays small.

Once a day the daemon deletes runs older than 30 days, a small batch at a time, and gives the space back to the disk. It always keeps each job's newest 20 runs. Set your own limits, or keep everything.

KEEP 90 DAYS · NEWEST 50 PER JOB
$ cronlog daemon --retain 90d --keep-last 50

Made for scripts and the people on call

Calm enough
to trust at 3:00 AM.

Every inspection command speaks JSON. Every job knows which run it is, and how the last one went.

JSON for scripts

    "run_id": 4821,
    "status": "success",
    "trigger_type": "schedule",
    "scheduled_for": "2026-11-18T09:45:00-05:00",

What each job is told
# set in every job's environment
CRONLOG_RUN_ID=4821
CRONLOG_JOB_NAME=sync
CRONLOG_SCHEDULED_FOR=2026-11-18 09:45:00
CRONLOG_TRIGGER_TYPE=schedule
CRONLOG_PREVIOUS_RUN_ID=4820
CRONLOG_PREVIOUS_STATUS=failed

# so a job can resume where the last one stopped
  • Restart recovery. Runs left running when the daemon stopped are marked interrupted, with a note in their log.
  • Parallel jobs. Each due job runs on its own thread, so a slow one never delays the others.
  • Bounded pilots. --max-runs 12 disables a job after 12 scheduled runs.
  • Missed runs. After downtime a job runs once, then picks up its normal schedule.

A job hangs✕ It runs until someone notices
The scheduler stops✕ Silence

Cronlog

Did it run?✓ cronlog history
What did it print?✓ Kept with the run
Still running from last time✓ Skipped, and recorded
A job hangs✓ Killed at its timeout
The scheduler stops✓ cronlog health exits 1

What it is not

Not a workflow orchestrator. Cron’s simple idea, with a durable audit trail.

Cronlog doesn't try to replace Airflow, Temporal or a job queue. Retries, checkpoints and publish-once logic belong in your pipeline. Cronlog gives that pipeline a reliable clock and a record it can read.

Free and open source

Running in
three steps.

  1. Step 1

    Build

    Needs a Rust toolchain. The binary lands in target/release/; put it on your PATH.
    git clone https://github.com/Plicerin/cronlog
cd cronlog
cargo build --release

  2. Step 2

    Add a job

    Commands run directly, not through a shell. For pipes and &&, call sh -c.
    cronlog add --name backup \
  --schedule "daily at 02:00" -- ./backup.sh

  3. Step 3

    Start the daemon

    Run it in a terminal, or as a systemd service using the runbook.
    cronlog daemon
